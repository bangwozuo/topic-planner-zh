# 使用示例

以下示例 1-2 来自 `scripts/dedup_check.py` 对 `examples/input.json` 的实跑结果
（退出码 0，2026-09-30）；示例 3-5 为模型侧复核的典型场景。

## 示例 1：标准输入 —— 5 候选 × 4 历史题 → 1 重复 4 通过

**输入**（节选，完整见 `examples/input.json`）：

```json
{
  "candidates": [
    {"title": "面试被问期望薪资怎么答：3 个话术模板", "source": "热榜候选"},
    {"title": "被裁员那天我在工位坐到凌晨：3 个动作保住赔偿金", "source": "竞品爆款"}
  ],
  "library": [
    {"title": "面试被问期望薪资怎么答：3 个话术模板", "days_ago": 35},
    {"title": "裁员赔偿金谈判：N+1 怎么算", "days_ago": 50},
    {"title": "汇报工作先说结论：金字塔原理的 3 步用法", "days_ago": 120},
    {"title": "节后综合症自救指南", "days_ago": 200}
  ]
}
```

**输出**：`out/选题去重清单.xlsx` + `out/dedup_check.json`。
「面试被问期望薪资怎么答」与 35 天前历史题相似度 1.00 → 🔴 重复，
其余 4 条字面通过。

## 示例 2：整改前后对照 —— 从「凭记忆查重」到「脚本 + 语义复核」

| 阶段 | 做法 | 结果 |
|---|---|---|
| 改造前 | 靠记忆判断「这题拍过没」，30 天拍 12 条后记忆开始混乱 | 「期望薪资话术」35 天内拍了两次，第二条播放只有第一条的 40%，评论区出现「又讲这个」 |
| 改造后 | 候选题先过脚本相似度 → 模型复核语义重复 → 重复题走差异化升级 | 重复率降为 0；「先说结论」题 120 天后以「汇报先讲数据变化」的新方法论翻新成功 |

**关键差异**：字面相似度抓「复制粘贴式重复」，语义复核抓「换皮式重复」，
两层都过才算查重通过。

## 示例 3：换说法同题（字面 0.25，语义重复，模型改判）

「领导让你口头汇报时，先说结论再说理由」vs 120 天前「汇报工作先说结论：
金字塔原理的 3 步用法」——用词完全不同，方法论相同。字面通过但语义重复，
这就是脚本必须有模型复核层的原因：二元组相似度对同义改写天然钝感。

## 示例 4：90 天重做窗口的用法

历史库 200 天前的「节后综合症自救指南」与候选「国庆假期后第一天上班，
怎么快速找回状态」相似度仅 0.08，直接通过。即使相似度落在 0.40-0.60，
超过 90 天的题也只判「相似（可重做）」而非重复——粉丝记忆窗口约为一个季度，
季度外的同题翻新是合法的长尾打法，前提是换角度（换人群/换场景/换步骤数）。

## 示例 5：空库不装查重

**输入**：`library: []`（新账号第一条内容）。

**输出**（实测）：脚本提示「历史库为空（新账号首条内容）：全部候选直接判通过」，
`候选 1 条：重复 0 / 相似可重做 0 / 通过 1`，正常退出；模型路如实输出
「历史库为空，无可比对项」。新账号不伪造查重记录，从第二题开始查重才有意义。
